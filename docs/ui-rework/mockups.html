2. Principles for every screen

  • Text is never scaled below 1:1. Screens reflow instead: two columns at ≥ 560 GUI px, one column with tabs below that. Lists scroll and have no caps.
  • One fixed frame per screen: a title bar (name, tier, hardcore), the content, and a bottom action bar that never scrolls away with one primary button (Ready / Start).
  • Fewer, larger elements: member cards 26 px tall with head, class and level; modifiers 18 px rows with the reward effect on the right. The long description goes in a tooltip.
  • Parchment like the Eden hub (EdenParchment colors) for screens. Dark translucent for the in-world HUD, because it has to read over any terrain.
  • Numbers are big where they matter: timer, boss HP %, rewards, your damage. Details go in tooltips.
  • One lobby view shared by the controller screens and the hub, so dungeon, raid and arena stop being three near-copies of 1,600–1,900 lines each.

8. Order of work (each step goes to TEST + Client TEST, with before/after screenshots at scale 2/3/4)

  1. Foundation: a responsive canvas (size = GUI area up to a max, reflow under 560), shared parts (title bar, action bar, member card, modifier row, pills, tier picker), 1:1 text.
  2. Lobby view (dungeon/raid/arena in one): My lobby, Lobbies, Leaderboard, Invites; rental row + preset modal; no row caps.
  3. Lobby browser + create API (createLobby/updateLobby, min level, activityInfo, possibleDrops) → Eden_LD builds the hub screens on it.
  4. HUD + ally sidebar: new timer/boss bar, arena wave panel, sidebar (server sends teammates' HP a few times a second, only on change).
  5. Run details + end-of-run screen with heads, class icons and the reward breakdown.

Client update: every step changes the client, so the pack and live go together, after TEST. Admin/editor screens are not part of this.
